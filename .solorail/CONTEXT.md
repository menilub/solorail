## 3. Domain Glossary (Ubiquitous Language)
- **Epic:** A large unit of user value (`E-01`, `E-02`, ...) tracked in `.solorail/ROADMAP.md` and detailed in `.solorail/epics/epic-XX.md`.
- **Issue:** A vertical tracer-bullet slice of an Epic, sized 1.0–4.0h, with a globally unique ID (`E01-ISS-01`) and status `TODO | IN_PROGRESS | BLOCKED | DONE | CUT`.
- **Spec Receipt:** `.solorail/specs/<ISSUE-ID>-spec.md`, the allowlisted file list + test plan an Issue must have before any code edit is permitted.
- **Gate:** The `PreToolUse` hook (`enforce_gate.py`) that blocks (exit code 2) any edit outside the active Issue's spec receipt allowlist.
- **Tracer-bullet:** A thin, end-to-end vertical slice of functionality sized small enough to implement and verify within one Issue.
- **Hotfix:** An urgent, ≤1.0h bug fix handled via `/solorail:hotfix` in an isolated worktree with a regression test, rolled into `ROADMAP.md` under `HOTFIX`.
- **Pivot:** A mid-sprint scope or requirement change absorbed via `/solorail:pivot`, marking dropped items `CUT` while preserving audit history.
- **Learned Guardrail:** A rule distilled from a sprint retrospective into `CONTEXT.md` Section 5 via `/solorail:evolve`, capped at 15 rules.
- **ADR (Architecture Decision Record):** A lightweight 4-line log entry in `CONTEXT.md` Section 4 for each irreversible technical choice.
- **Linked Worktree:** A secondary Git worktree (e.g. a Conductor-managed one, or one `architect-issue` previously created) whose `git rev-parse --git-dir` differs from `--git-common-dir`. `architect-issue` skips offering to create a nested worktree when already inside one; the primary/main checkout does not count as "linked" and still gets the offer.

## 4. Architecture Decision Records (ADRs)
> Append lightweight 4-line ADRs here whenever an irreversible technical choice is made.

- **ADR-001 (2026-11-24):** Restart plugin versioning at `0.4.0-beta` instead of continuing from `2.7.3` — *Context:* No installs or public releases exist yet; `2.7.3` overstated maturity for a pre-release beta. — *Consequence:* `plugin.json`, `marketplace.json`, and README references must be kept in sync going forward; prior git commit messages mentioning `v2.7.x` remain as historical artifacts, not live version claims.
- **ADR-002 (2026-11-24):** Enforce the `main`/`master` edit block in `scripts/enforce_gate.py` (code-level, exit 2) rather than only in `build-issue`'s prose instructions — *Context:* A prose-only warning can be ignored by the executing agent; Epic E-02 requires a hard block. — *Consequence:* `enforce_gate.py` now depends on `git rev-parse --abbrev-ref HEAD`; a detached-HEAD or non-Git context is treated as unprotected (fails open), matching its existing fail-open behavior for a missing `.solorail/` dir.
- **ADR-003 (2026-11-24):** `verify-issue`'s computed `Actual` hours use raw wall-clock elapsed time between `Started At` and verification (rounded to the nearest 0.5h, 0.5h floor) — explicitly confirmed over a file-mtime-delta alternative despite counting idle/conversation gaps. — *Context:* User confirmed the literal spec text (system clock) over the E01-ISS-02/03 mtime-delta precedent, which filters idle time but isn't what the issue asked for. — *Consequence:* Sprint velocity numbers computed by this path may run far above real working time on multi-turn issues; this is accepted, not a bug.

- **ADR-004 (2026-11-24):** Sprint files keep **both** the `## Metrics` table and the `## Time & Velocity Summary` block, with `sync_metrics.py` writing both from one set of computed totals — rather than deleting either block. — *Context:* The two blocks disagreed because only the summary was script-written; user chose "keep both, synced" so no content is removed from existing sprint files. — *Consequence:* Two render paths must stay in agreement forever; a future format change must update both, and `replace_block` must remain non-destructive or the lower block will eat the upper one's neighbours. The duplication is accepted in exchange for not rewriting existing sprint history.

## 5. Learned Guardrails (Updated via /solorail:evolve)
- **Test "inside a worktree" detection against the main checkout, not just secondary ones.** `git worktree list` reports the primary checkout too, so a naive membership check flags it as "inside a worktree" and silently breaks the normal case. Verify both branches of any worktree-aware logic live, in the main checkout and in a linked worktree, before closing the issue. (From E02-ISS-01.)
- **When an issue's wording allows two different implementations (e.g. "system clock / file mtimes"), ask before building, not after.** A prior sprint's own precedent (file-mtime deltas in E01-ISS-02/03) silently conflicted with this sprint's literal spec text (raw wall-clock). Surfacing it up front avoided a wasted build-and-redo cycle. (From E02-ISS-03.)
- **Estimation Accuracy Ratio was 0.50 this sprint** (issues took ~half their estimate) **for small, surgical fixes** (one helper script + tests + a one-line `SKILL.md` prose edit). Bias future estimates for this shape of issue downward, or split "add enforcement in code" from "update skill prose" if they consistently run shorter than planned. (From E02-ISS-03.)
- **Sprint 02 Accuracy Ratio: 0.37.** All 9 issues ran 60% under estimate. Root causes: (a) test-driven approach enabled fast iteration; (b) the codebase is now stabilizing—no more architectural rewrites; (c) small surgical fixes (one file + test suite) are inherently faster than initially estimated. Bias all future estimates downward by ~40–50% for this repository shape. (From E03-ISS-01 through ISS-09.)
- **Plugin cache staleness is self-hosting dev friction, not a product bug — correcting Sprint 02's guardrail.** That guardrail recommended sourcing skill scripts from the target repo's `.solorail/scripts/` instead of the plugin cache. Building that as E04-ISS-02 would have violated PRD §4 ("plugin logic stays in Claude Code's plugin cache, not the target repo") — correct for every *installed* user, who always gets current HEAD. Only this repo, being the plugin's own source, suffers a stale local cache between merges; the fix is `/plugin update solorail`, not product code. Caught before building, via a pre-architecture scope check against the PRD. (From E04-ISS-02, cut via Pivot.)
- **A markdown table parser that unconditionally skips "row 2" as the separator will silently drop real data the moment that row is missing or displaced.** `parse_markdown_table` assumed the line right after any table header was always the `|---|---|` divider. An Edit that inserted data rows directly after the header (instead of after the divider) pushed the real divider out of position, and the parser kept skipping whatever landed in that slot — one real issue row vanished from every Est/Done count with no error. Any fixed-position table parser needs to check a row's actual shape before treating it as structural. (From BUG-01.)
- **Sprint 03 Accuracy Ratio: 0.25 — rescoping work estimates differently than build work.** 3 of 4 issues were architecture-stage verification/rescoping (confirm alignment, cut a conflicting plan, write a publish log) rather than new code; they ran ~75% under estimate. When an issue's likely resolution is "verify and rescope" rather than "build," estimate it closer to 0.25–0.5h regardless of the epic's original hour guess. (From E04-ISS-01, ISS-03, ISS-04.)
- **A file that exists both in this repo and in the installed plugin cache must be edited and tested at its repo path, never the cache's.** E04-ISS-01 edited and tested `~/.claude/plugins/cache/solorail/solorail/<version>/skills/evolve/SKILL.md` directly — the live install, not `skills/evolve/SKILL.md` in this repo, which is what actually ships. The test's assertion path was hardcoded to that same cache location, so it passed the whole sprint while the real source was never touched; `v0.4.0-beta` was tagged and pushed in that broken state. Any test asserting on this repo's own source must resolve its target relative to the repo root (e.g. `os.path.dirname(os.path.dirname(os.path.abspath(__file__)))`), never an absolute path into an installed copy. (From BUG-02.)
